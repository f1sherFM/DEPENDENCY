# Сохранённые исследования

Исследование — имя, текстовая заметка и состояние обычного графа на **конкретном сохранённом снимке**. Новый анализ проекта создаёт другой снимок и не изменяет исследование.

## Использование

1. Откройте граф, настройте каталог, поиск, тип и направление связей, выбранный узел, масштаб и положение камеры.
2. Нажмите «Сохранить исследование», задайте имя и заметку.
3. После перезапуска откройте проект → «Исследования» → «Открыть исследование».

Открывается исходный снимок исследования. Текущий latest snapshot проекта не заменяется, анализ исходников не запускается. Удалённые или изменённые исходники не мешают открыть уже сохранённый снимок.

Сохраняются режим files/directories, каталог, поиск, показ внешних пакетов, тип рёбер, focus/direction, выбранный node ID, состояние контекстной панели и камера. Центр камеры хранится в координатах графа вместе с масштабом: на другом размере окна восстанавливается та же область, а не старые экранные пиксели. На меньшем экране может быть видно меньше узлов; «Вписать граф» остаётся отдельным действием.

Изменения графа сохраняются явно. У открытого исследования можно обновить запись или выбрать «Сохранить как новое». Кнопка «Закрыть исследование» возвращает обычный граф. Редактирование заметки из списка сохраняет исходный граф. Удаление требует подтверждения и удаляет только исследование, не анализ, снимок или AST cache.

Выборки диагностик и сам граф выборки Impact пока не сохраняются: кнопка объясняет, что нужно перейти во «Весь проект». Автоматического переноса исследования на новый снимок нет; восстановление не подменяет отсутствующие ID похожими файлами.

## Данные и совместимость

- SQLite schema 3: отдельная таблица investigations с FK на snapshots. project ID выводится через snapshot, поэтому нельзя сохранить противоречивую пару project/snapshot.
- Обновление schema 2 → 3 транзакционное. Результаты анализа, imports и mutable parser cache не пересчитываются и не переписываются. Старое приложение 0.8 не открывает schema 3; для отката нужна резервная копия до обновления при закрытом приложении.
- State version 1 относится к формату и текущей раскладке графа. Неизвестный формат виден в списке, но не восстанавливается и не перезаписывается этой версией.
- Обновление защищено revision: параллельная правка не затирается. При конфликте диалог сохраняет введённый текст и предлагает открыть свежую запись.
- Название — 1–120 символов, заметка — до 16000, state JSON — до 64 КиБ. Фильтры/ID проверяются по самому снимку. Текст остаётся текстом, не выполняется и не интерпретируется как HTML.

Тесты проверяют reopen базы, отсутствие исходников, исторический snapshot после нового анализа, CAS-конфликт двух writers, rollback ошибки записи, FK, неизвестный state version и неизменность snapshot/cache. Browser smoke проверяет сохранение/восстановление после reload и смены viewport, selected/query/camera, редактирование заметки и подтверждённое удаление; вызовов analysis IPC при этом нет.

## Выводы из Impact (разработка 1.0)

«Сохранить выводы» создаёт новую запись, не обновляя открытое исследование. Заметка содержит снимок, версии, исходные файлы, типы связей, глубину, результаты и ограничения обхода, фильтры списка и открытый сегмент доказательного пути. Частичные результаты явно записываются как нижние границы. Длинная запись сокращается с явным предупреждением; текст можно отредактировать перед сохранением.

Граф записи показывает входящее окружение первого исходного файла на том же снимке. При повторном открытии восстанавливается этот обычный граф, а параметры и выводы доступны в заметке. Полный список Impact, все пути и запрос автоматически не восстанавливаются. Диалог сообщает об этом до сохранения. Данные снимка не пересчитываются, schema/state не меняются.

## Перенос исследования (разработка 1.0)

В разделе «Исследования» кнопка «Экспортировать» сохраняет новый `*.dependency.json`; существующий файл не перезаписывается. Файл содержит заметку, состояние графа, результат и inventory исходного снимка, его дату и версии. Исходники и parser cache не включены. Пути, названия, Git metadata и текст заметки могут быть чувствительными: проверьте JSON перед передачей.

Для импорта выберите локальный проект и откройте «Исследования → Импортировать исследование». Предпросмотр показывает имя, заметку, происхождение, версии и количество записей. До «Импортировать копию» база не меняется. Отмена ничего не записывает. При подтверждении файл перечитывается с лимитом 64 МиБ, проверяется SHA-256 просмотренных байтов (это защита от изменения файла, не цифровая подпись), формат v1 и graph state v1, уникальность узлов/рёбер/путей, наличие концов связей и корректность сохранённого графа.

Импорт создаёт новые ID снимка и исследования в выбранном проекте, одной SQLite-транзакцией. Существующие снимки, latest snapshot и parser cache не меняются; повторный импорт создаёт ещё одну копию. Исходные версии анализатора/правил и результат сохраняются; повторного анализа нет. Inventory восстанавливается для чтения/сравнения. Связь импортированных путей с локальными исходниками не подтверждается. Повторный анализ всегда использует локальный корень выбранного проекта.

Неизвестный формат отклоняется, автоматической конвертации будущих версий нет. Открытие импортированного исследования использует существующий механизм исторических снимков. Для импорта сейчас нужен уже открытый локальный проект; отдельная библиотека переносимых проектов не реализована.
