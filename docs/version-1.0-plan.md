# 1.0.0 Open Beta: исследование проекта

Статус: 1.0.0 Open Beta. Ручная проверка владельцем выполнена на 1.0.0-beta.1; [итоговый отчёт](version-1.0-validation.md).

## Пользовательские маршруты

1. **Познакомиться:** открыть проект → увидеть область анализа и дату снимка → понять крупные части → раскрыть интересующий каталог.
2. **Разобраться:** найти файл → изучить входящие/исходящие связи → открыть основания связи → проверить архитектурную находку и ограничения достоверности.
3. **Подготовить изменение:** выбрать файл → изучить потенциальных потребителей и пути → записать выводы → сохранить исследование → продолжить после перезапуска.

При повторном открытии сначала доступен сохранённый результат. Новый анализ — явное действие. Отсутствие диагностики не означает доказанное отсутствие проблемы. Каталоги не называются архитектурными слоями без пользовательского определения.

## Первый вариант карты

Обзор больше не выбирает первые 36 файлов. Сначала каждый непосредственный каталог представлен одним блоком; файлы текущего каталога собраны отдельно. Изолированные части сохраняются. Направление — источник использует цель. В одну стрелку объединяются связи между той же парой групп, типы и все исходные рёбра доступны в evidence с порционным раскрытием.

По умолчанию показано 12 частей, остальное раскрывается явно. Под картой учитываются связи внутри групп, за границей области и скрытые лимитом. Внешние пакеты доступны в полном графе. Выделение и открытие evidence не перестраивают раскладку. Карта имеет собственную прокрутку: текст не уменьшается до нечитаемых размеров ради вписывания.

Связи за границей раскрытого каталога доступны группами по направлению и внешнему каталогу, с исходными местами и переходом к файлу или каталогу. Состояние обзорной карты пока не входит в сохранённые исследования; исследования полного графа 0.9 не меняются. Перед завершением этапа нужно проверить плотные двунаправленные графы и найти удобный переход к внешним потребителям.

## Первый аудит движка

Rust: `workspace.dependencies` с `path` ранее не формировал подтверждённую связь с локальным crate. Теперь путь относится к определяющему workspace, учитывается явный `package.workspace` внутри захваченной области, отсутствующее наследование диагностируется. Сверяются имя package и наличие lib target. Формат parser facts и SQLite не меняется: rust-parser-1 сохранён, resolver повышен до rust-resolver-3, rules до diagnostics-5+resolver-6. Исторические снимки не переинтерпретируются.

Правила Cargo: [workspaces](https://doc.rust-lang.org/cargo/reference/workspaces.html), [workspace inheritance RFC](https://github.com/rust-lang/rfcs/blob/master/text/2906-cargo-workspace-deduplicate.md).

Исходный read-only прогон доступной Desktop-копии wemake_PS (HEAD a275c5adc8d31424897cb26241fd83aa86863b2a): 409 исходников, 2817 рёбер всех типов, 893 ограничения from-import bindings, 3 dynamic imports, 631 сообщение отсутствия уникального локального Python module (включая внешние импорты). Одна parse-error в tests/fixtures/noqa/noqa313.py с новым синтаксисом параметров типов; это не повод выключать диагностику или молча исключать тесты. Числа относятся к конкретной локальной копии и не доказывают полноту графа. Исходники, Makefile, setup и hooks проекта не запускались.

Этап статических Python bindings выполнен: файловая зависимость, импорт атрибута и реэкспорт различаются, неоднозначность сохранена. Поддержаны defaults параметров типов Python 3.13 через локальное дополнение грамматики; найденный parse-error устранён. Повторные прогоны, профили и границы — в [описании resolver](python-resolution.md). Произвольное сопоставление distribution → module запрещено.

## Проверки первого этапа

- Unit tests карты: сохранность исходных данных, точные счётчики/типы/evidence, границы каталогов, изолированные группы, ограничения больших карт.
- Browser smoke: обзор, keyboard evidence без смещения карты, раскрытие 36 файлов через группу/лимит, переход в полный граф; прежние Git/Impact/research сценарии остаются.
- Rust regression сначала воспроизвёл пропущенную workspace-path связь. Затем проверены обычный/явный workspace, отсутствие наследуемой декларации, отсутствие повторного parsing при смене manifest.
- Для конечной приёмки нужны собственные Rust/Python проекты пользователя и независимые сторонние репозитории. Единственный успешный fixture или запуск на другом ПК не заменяет три сквозных пользовательских задания.

Локальный результат первого этапа: 67 Rust tests passed (3 profiling/export tests отдельно от обычного набора), 20 Node tests passed; TypeScript/Vite, rustfmt, Clippy с warnings denied и repository checks прошли. Git browser smoke прошёл с сохранением исследований и новой картой. В браузере mocked только Tauri transport: native проверка новой карты ещё не выполнялась. Установщик 1.0 не выпускался, установленная 0.9 не заменялась.

Новые языки, полная компиляция/исполнение исследуемого кода, облачная синхронизация и встроенный AI-ассистент не входят в согласованный первый объём 1.0.

## Связность исследования

Карта хранит раскрытую область, лимиты, выбранную связь и прокрутку до смены снимка. Переход к файлу открывает контекст; переход по связи показывает настоящий importer/line/type и оба конца. Из графа доступен возврат к карте, из Impact — к прежнему графу с камерой, фильтрами, диагностическим/Impact scope и выбранной связью. Дата и ID снимка видны в заголовке.

В Impact можно сохранить выводы как новое исследование: параметры обхода, ограничения покрытия, частичные счётчики как нижние границы, фильтры списка и открытый сегмент пути записываются в редактируемую заметку. Восстанавливаемый граф — обычное окружение потребителей первого исходного файла. Диалог объясняет это до записи; полный список Impact и состояние его запроса не сериализуются. История и формат schema 3/state 1 сохранены. Устаревший, загружаемый или ошибочный результат сохранять нельзя.

Проверки этого шага: 24 Node tests, TypeScript/Vite, repository checks и два browser smoke на настоящих engine exports (Impact и Git). Transport Tauri в браузере подменён; новой проверки Windows WebView/установщика на этом шаге нет. 1.0 ещё не выпущена.
