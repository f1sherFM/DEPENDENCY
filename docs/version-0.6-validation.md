# Проверка DEPENDENCY 0.6.0

## Что проверено

- Reverse BFS: цепь, ромб с альтернативными маршрутами, циклы, self-loop, изолированный файл, несколько корней. Для каждого пути — исходное направление импортов и минимальные расстояния; исходные точки не входят в affected counts.
- Фильтры type-only/dynamic/static применяются до обхода. Поиск и кандидаты тестов фильтруют готовую выборку и сохраняют промежуточные узлы пути.
- Различие complete/partial при ограничениях глубины, узлов, проверенных рёбер и времени; совпадение численного лимита с полным завершением не вызывает ложный partial.
- Цепь 50 001 узел / 50 000 рёбер: максимальное расстояние 50 000, сегменты пути по 200 без рекурсии. Широкое дерево с 50 000 прямых потребителей и страницы без дублей. Плотный граф 150 узлов / 22 500 рёбер с искусственным бюджетом 500 для проверки неполноты.
- Исторический snapshot после удаления каталога исходников; повторное использование query/index, истёкшие query IDs после замены запроса, неверные узлы/типы/глубины/страницы. JSON старых снимков не изменяется, новый latest snapshot не заменяется историческим запросом.
- Метаданные legacy, отключённые/неполные правила диагностики и неизвестные виды рёбер не превращаются в гарантию полноты. Версии parser/rules и схема SQLite остаются прежними.

`cargo test`: 34 passed, 2 ignored (ручные профилировщики). `cargo clippy --all-targets -- -D warnings` и форматирование проходят. `npm test`: 11 тестов модели графа, включая приоритет корней при лимите рисунка. TypeScript и production frontend build проходят. Windows-дистрибутив собирается через `npm run tauri build`.

## Воспроизведение

PowerShell, из `src-tauri`:

```powershell
$env:DEPENDENCY_DUMP_DIR = Join-Path $env:TEMP 'dependency-060-check'
$env:DEPENDENCY_PROFILE_ROOTS = 'C:\path\DEPENDENCY;C:\path\DISKMAP'
cargo test profile_and_export_impact -- --ignored --nocapture
```

Профилировщик создаёт snapshot настоящим Analysis Engine, сохраняет его в временную SQLite, запрашивает impact через production API и выгружает `impact-ui.json` с настоящими summary/page/path. Переменная PROFILE_ROOTS необязательна: без неё проверяется только встроенный fixture.

Из корня проекта, после `npm run build`:

```powershell
node tests/ui-smoke.mjs "$env:TEMP\dependency-060-check\impact-ui.json" 'C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe'
```

Используются Node.js 24, установленный Chromium, отдельный временный профиль браузера и локальный сервер для `dist`. Зависимости браузерного драйвера не добавляются.

UI-тест подменяет только Tauri IPC: обход берётся из JSON реального Rust-результата. Фильтрация маленькой страницы выполняется в транспортной заглушке; маршруты берутся из engine output. Проверены выбор файла, типы импортов, partial counts, тестовый фильтр, доказательный путь, приоритет/подсветка корней в графе, объединение нескольких корней, пустой результат, ошибка истёкшего query и повтор запроса. Искусственно задержанный старый ответ не заменяет новый результат. Также проходят прежние сценарии диагностики, больших/пустых списков и legacy snapshots. Screenshots сохраняются во временный каталог и проверены визуально.

## Практические ограничения

- Это файловая достижимость, не семантический прогноз поломки. Framework conventions, вычисляемые пути и неподдерживаемые языки ограничивают граф.
- Бюджет 2 секунды относится к обходу; SQL, десериализация, индекс, сортировка, очередность запросов и формирование страниц имеют отдельные затраты. Прерывания backend-запроса пользователем пока нет; UI игнорирует устаревший ответ.
- Индекс оценивается консервативной формулой (структуры, пути, строки рёбер и запас на индексы), а не измерением RSS. Пределы 64 МиБ JSON и 256 МиБ оценки индекса защищают этот путь запросов, но не ограничивают память уже открытого полного frontend snapshot или всего процесса.
- Страница/сегмент в графе — ограниченная проекция. Не все промежуточные пути входят в рисунок страницы; для обоснования отдельного потребителя используйте «Почему затронут».
- Browser smoke проверяет frontend и контракт ответов, но не нативный выбор папки и не транспорт WebView2↔Tauri. Storage/API/обход проверены Rust-тестами; Windows installer — сборкой. Полный ручной прогон нативного UI отдельно не заявляется.
