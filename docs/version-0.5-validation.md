# Проверка 0.5.0

## Автоматические сценарии

- Цикл, в котором сортировка SCC не задаёт реальных рёбер; самоссылки, type-only, dynamic-only, смешанные циклы; замкнутый маршрут на 15 000 узлах без рекурсии.
- Подсчёт уникальных fan-in/out, повторные импорты, barrel reexports, исключение npm/type-only/self рёбер.
- Защита entry points `main`/`module`/`exports`/`bin`, workspace manifests, тестов, деклараций и config файлов.
- Неполный AST, неразрешённые импорты, не-UTF-8 исходники, отключённые правила, исключения, ошибочные и слишком большие настройки.
- Переоткрытие SQLite, неизменность старых снимков, отказ публикации при неверной конфигурации и ошибке транзакции; reuse AST при изменении только настроек; обновление старого parser cache с неверной классификацией type-only.
- Проекция всего набора узлов диагностики в граф, счётчик связей за границами набора и прежние тесты 0.4.

Команды: `npm test`, `npm run build`; в `src-tauri`: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`.

В первом проекте учитываются только поддерживаемые исходники, Rust не анализируется. Числа меняются при добавлении файлов. Конфигурации и скрипты исследуемых проектов не выполнялись; их данные не изменялись.

На двух небольших реальных проектах значения 20/30 не создают сигналов высокой связанности. Выборки недостаточно для универсальной калибровки: пороги оставлены явными настраиваемыми ориентирами. Шум от framework entry points ограничивается уровнем info, текстом ограничения и `exclude`; автоматического объявления «мёртвого кода» нет.

Воспроизведение на выбранных локальных репозиториях (PowerShell, из `src-tauri`):

```powershell
$env:DEPENDENCY_PROFILE_ROOTS = 'C:\path\project-one;C:\path\project-two;C:\path\DEPENDENCY\src-tauri\tests\fixtures\diagnostics'
$env:DEPENDENCY_DUMP_DIR = Join-Path $env:TEMP 'dependency-050-check'
cargo test profile_selected_repositories -- --ignored --nocapture
```

Эта проверка по умолчанию ignored: читает только явно заданные каталоги и при заданном DUMP_DIR записывает отдельные JSON-результаты вне SQLite приложения.

## Интерфейс

`tests/ui-smoke.mjs` запускает отдельный headless Chromium с временным профилем и локальным HTTP-сервером, обслуживающим `dist`. Реальные результаты Rust передаются в интерфейс через подмену только Tauri IPC. Проверяются загрузка результатов, фильтр cycle, маршрут, переход к набору узлов в графе, возврат в Problems, раскрытие каталогов и legacy snapshot. Дополнительные большие/пустые списки моделируются для проверки UI-пагинации. Проверка завершается с ошибкой при JS exception; screenshots сохраняются во временный каталог для визуального осмотра.

```powershell
node tests/ui-smoke.mjs "$env:TEMP\dependency-050-check\analysis-2.json" 'C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe'
```

Тест использует установленный Chromium и Node.js 24; зависимости для браузерного драйвера не добавляются. Он проверяет frontend, но не нативный диалог выбора папки и не настоящий Tauri IPC. Backend и SQLite проверяются Rust-тестами, Windows-дистрибутив — `npm run tauri build`.
